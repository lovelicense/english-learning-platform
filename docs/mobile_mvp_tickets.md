# 모바일 MVP 티켓 정리

## 목적
- 현재 웹에서 이미 동작하는 핵심 흐름을 기준으로 모바일 우선 개발 순서를 정리한다.
- 모바일은 처음부터 웹의 모든 기능을 옮기기보다, `수집 -> 정리 -> 자산화 -> 듣기` 루프를 먼저 완성한다.
- 1차 목표는 `모바일에서 녹음 -> 업로드 -> STT 확인 -> 문장 수정 -> 영어 표현 생성 -> TTS 재생`이다.


## 우선순위 기준
- 사용자 가치가 큰가
- 모바일에서만 강한 사용성이 있는가
- 다음 단계 기능의 선행 의존성인가
- 웹의 기존 API/워커 구조를 재사용할 수 있는가


## 1차 MVP 범위
1. 실제 음성 녹음
2. recording session 기반 업로드
3. 업로드/처리 상태 확인
4. STT + diarization 결과 확인
5. 문장 수정 / 내 화자 선택
6. 영어 표현 생성
7. TTS 재생
8. 표현 목록/상세 최소 조회


## 티켓 목록

### Ticket A. 모바일 실제 녹음 붙이기
- 목표:
  - Expo 기반으로 실제 마이크 녹음을 시작/종료할 수 있게 한다.
- 범위:
  - 마이크 권한 요청
  - 녹음 시작 / 종료
  - 녹음 중 경과 시간 표시
  - 녹음 파일 로컬 경로 확보
  - 실패/권한 거부 처리
- 주요 화면:
  - `apps/mobile/app/(tabs)/record.tsx`
- 완료 조건:
  - 모바일에서 실제 오디오 파일 1개를 안정적으로 생성할 수 있다.
- 비고:
  - 장시간 녹음 안정성을 위해 파일 포맷과 플랫폼 차이를 먼저 확인한다.

### Ticket B. recording session 업로드 연결
- 목표:
  - 실제 녹음 파일을 현재 백엔드의 `recording session` 흐름에 연결한다.
- 범위:
  - 세션 생성
  - presign 발급
  - 파일 업로드
  - 필요 시 complete 호출
  - finalize 호출
  - process 호출
- 주요 연동:
  - `apps/mobile/src/lib/api/recording-sessions.ts`
- 완료 조건:
  - 모바일에서 녹음 후 서버 처리 큐까지 정상 진입한다.
- 비고:
  - 초기에는 단일 파일 업로드로 시작하고, 이후 파트 업로드로 확장 가능하다.

### Ticket C. 업로드/처리 상태 화면 정리
- 목표:
  - 사용자가 현재 세션이 어디까지 처리됐는지 모바일에서 바로 알 수 있게 한다.
- 범위:
  - 업로드 중 / 업로드 완료 / 처리 대기 / 처리 중 / 완료 / 실패 상태 표시
  - polling 흐름 정리
  - 에러 메시지 노출
  - 업로드 파트 / 작업 큐 표시 유지
- 주요 화면:
  - `apps/mobile/app/(tabs)/record.tsx`
- 완료 조건:
  - 사용자가 세션 상태를 새로고침 없이도 이해할 수 있다.

### Ticket D. 녹음 상세 STT 결과 화면 구현
- 목표:
  - 모바일에서 STT 결과와 화자 분리 결과를 확인할 수 있게 한다.
- 범위:
  - 세그먼트 목록
  - speaker / start / end / text 표시
  - 세션 요약 정보 표시
- 주요 화면:
  - `apps/mobile/app/recording/[id].tsx`
- 완료 조건:
  - 웹의 `음성 데이터 수집 / 텍스트 정리` 핵심 읽기 흐름을 모바일에서도 확인 가능하다.

### Ticket E. 문장 수정 / 삭제 기능
- 목표:
  - STT 결과를 모바일에서 후편집할 수 있게 한다.
- 범위:
  - 텍스트 수정
  - 불필요 문장 삭제
  - 저장
  - 저장 후 화면 즉시 반영
- 완료 조건:
  - 모바일에서 문장 정리까지 끝낼 수 있다.
- 비고:
  - 표현 생성 전 반드시 필요한 선행 티켓이다.

### Ticket F. 내 화자 선택 기능
- 목표:
  - diarization 결과에서 내 발화를 골라 후속 표현 생성 품질을 높인다.
- 범위:
  - speaker 목록 노출
  - `isMine` 지정
  - 저장
- 완료 조건:
  - 여러 화자 대화에서도 내 발화 중심 파이프라인이 가능하다.

### Ticket G. 영어 표현 생성 연결
- 목표:
  - 수정된 한국어 문장을 영어 표현 자산으로 변환한다.
- 범위:
  - 표현 생성 API 호출
  - `easy / base / natural / note` 표시
  - 생성 상태 / 실패 상태 표시
- 웹 대응 기능:
  - `영어 표현 생성 / 영어 음성 생성`
- 완료 조건:
  - 모바일에서 한국어 자산을 영어 표현 자산으로 전환할 수 있다.

### Ticket H. TTS 재생 붙이기
- 목표:
  - 생성된 표현을 모바일에서 바로 들어볼 수 있게 한다.
- 범위:
  - 표현별 TTS 재생
  - 재생 상태 표시
  - 필요 시 presigned URL 재생 처리
- 완료 조건:
  - 표현 생성 직후 듣기 학습이 가능하다.

### Ticket I. 표현 목록 / 상세 최소 구현
- 목표:
  - 저장된 표현을 다시 찾아 학습할 수 있게 한다.
- 범위:
  - 표현 리스트 조회
  - 표현 상세 진입
  - 한국어 / 영어 / 메모 / TTS 확인
- 주요 화면:
  - `apps/mobile/app/(tabs)/expressions.tsx`
  - `apps/mobile/app/expression/[id].tsx`
- 완료 조건:
  - 한 번 만든 표현을 모바일에서 재활용할 수 있다.

2. Ticket B: 업로드 연결
3. Ticket C: 상태 화면 정리
4. Ticket D: STT 결과 화면
5. Ticket E: 문장 수정 / 삭제
6. Ticket F: 내 화자 선택
7. Ticket G: 영어 표현 생성
8. Ticket H: TTS 재생
9. Ticket I: 표현 목록 / 상세
10. Ticket J: 표현 연습
11. Ticket K: 오늘의 복습
12. Ticket L: TTS 완료 표현 모아보기
13. Ticket M: 영어 AI 대화
14. Ticket N: 다이얼로그 연습


## 왜 이 순서인가
- 모바일의 가장 큰 장점은 `즉시 녹음`이므로, 수집 기능이 최우선이다.
- 녹음 뒤 결과를 바로 확인하고 수정할 수 있어야 원천 데이터 품질이 올라간다.
- 영어 표현 생성과 TTS는 현재 서비스의 핵심 가치이므로 1차 MVP 안에 포함한다.
- 연습/복습/AI 대화는 가치가 크지만, 원천 수집과 자산화 루프가 먼저 안정화되어야 한다.


## 바로 착수할 3개
- Ticket A: `record.tsx`에 실제 녹음 붙이기
- Ticket B: presign 업로드 + finalize/process 연결
- Ticket D: `recording/[id].tsx`에 STT 결과 상세 화면 만들기
