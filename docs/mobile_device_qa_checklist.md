# 모바일 QA 체크리스트

## 목적
- Expo 모바일 앱의 현재 MVP 흐름을 단계적으로 점검한다.
- 지금 바로 개발 가능한 `모바일 웹/개발 프리뷰` 검증 항목과, 나중에 꼭 확인해야 하는 `실기기 전용` 항목을 분리한다.
- 구현 완료된 `로그인 -> 녹음/업로드 -> STT 확인 -> 문장 수정 -> 표현 생성 -> TTS -> 복습` 루프의 회귀 테스트 기준으로 재사용한다.


## 테스트 대상 범위
- `apps/mobile`
- 주요 화면
  - `/(auth)/login`
  - `/(tabs)/home`
  - `/(tabs)/record`
  - `/recording/[id]`
  - `/(tabs)/expressions`
  - `/expression/[id]`
  - `/expression/[id]/practice`
  - `/(tabs)/reviews`
  - `/(tabs)/settings`


## 테스트 모드 구분

### 1. 모바일 웹 / 개발 프리뷰
- 목표:
  - UI 흐름, 상태 전이, API 연결, 에러 메시지, 편집 UX를 빠르게 검증한다.
- 장점:
  - 연결 셋업이 단순하고 반복 확인이 빠르다.
- 한계:
  - 실제 마이크 권한, 실기기 오디오 재생, 실제 녹음 파일 안정성은 완전히 대체할 수 없다.

### 2. 실기기 전용 테스트
- 목표:
  - 마이크 권한, 실제 녹음, 오디오 재생, 네트워크/USB/기기별 차이를 검증한다.
- 우선순위:
  - 모바일 웹에서 UI/흐름이 충분히 정리된 뒤 마지막 검증용으로 본다.


## 공통 사전 준비

### 1. 서버/인프라
- API 서버 실행
  - `pnpm dev:api`
- worker가 필요한 흐름이면 같이 실행
  - `pnpm dev:worker`
- DB / Docker 기동
  - `docker compose -f infrastructure/docker/docker-compose.yml up -d`
- S3 / OpenAI 관련 `.env` 값 확인

### 2. 계정 / 데이터
- 로그인 가능한 테스트 계정 준비
- 표현 / 복습 목록 테스트용 기본 데이터 확인


## A. 모바일 웹 / 개발 프리뷰에서 오늘 바로 볼 것

### A-1. 로그인 / 세션
- [ ] `login` 화면 진입 가능
- [ ] 이메일/비밀번호 입력 가능
- [ ] 로그인 성공 시 홈 또는 탭 화면으로 이동
- [ ] `settings`에서 stored email / server email 표시 확인
- [ ] `세션 새로고침` 정상 동작
- [ ] `로그아웃` 후 세션 정보가 비워지는지 확인
- [ ] 로그아웃 후 보호 API 호출 시 비정상 상태가 남지 않는지 확인

메모:
- API 주소가 잘못되었을 때 로그인 실패 메시지가 이해 가능한지 같이 확인

### A-2. Home / Settings
- [ ] `home`에서 Record / Reviews / Expressions / Settings 진입 카드 노출 확인
- [ ] `settings`에서 계정 카드 노출 확인
- [ ] `기본 세션 제목` 저장 가능
- [ ] `녹음 종료 후 자동 업로드` 토글 저장 가능
- [ ] `업로드 후 결과 상세 자동 열기` 토글 저장 가능
- [ ] `기본 답변 모드` 저장 가능
- [ ] `질문 한국어 TTS 자동 재생` 토글 저장 가능
- [ ] `질문 후 자동 녹음 시작` 토글 저장 가능
- [ ] 저장 후 `record`, `reviews`, `expression practice`에서 설정값이 반영되는지 확인
- [ ] 개발 빌드에서는 `Developer API Base URL` 카드가 보이는지 확인
- [ ] API 주소 저장 후 재시작 없이 다음 요청부터 새 주소가 반영되는지 확인

### A-3. Record 화면 상태 UX
- [ ] `record` 진입 가능
- [ ] 세션 제목 입력/초기값 표시 확인
- [ ] 업로드 전/후 버튼 활성화 조건 확인
- [ ] 세션 status / parts / jobs 영역에 상태가 반영되는지 확인
- [ ] 업로드 상태/처리 상태 메시지가 자연스러운지 확인
- [ ] 자동 업로드 옵션 안내가 현재 설정값과 일치하는지 확인

메모:
- 모바일 웹에서는 실제 마이크 녹음보다 상태 흐름, 안내 문구, 버튼 우선순위 검증이 중심

### A-4. STT 상세 / 문장 정리
- [ ] `recording/[id]` 상세 진입 가능
- [ ] diarization speaker 목록 노출
- [ ] 전체 / 내 화자 / 다른 화자 필터 동작 확인
- [ ] utterance 목록 렌더링 확인
- [ ] 문장 수정 후 저장 가능
- [ ] 문장 삭제 가능
- [ ] 미저장 변경 표시 노출 확인
- [ ] `내 화자 선택` 저장 가능
- [ ] 변경 후 화면이 즉시 갱신되는지 확인
- [ ] 연결된 표현 미리보기와 `표현 보기` 이동 동작 확인

### A-5. 영어 표현 / TTS
- [ ] utterance 기준 영어 표현 생성 가능
- [ ] 생성 결과 `easy / base / natural / note` 표시 확인
- [ ] 생성된 표현 수가 기본 정보 카드에 반영되는지 확인
- [ ] 표현 상세로 이동 가능
- [ ] 이미 생성된 표현이 표현 목록에서도 조회되는지 확인

메모:
- 모바일 웹에서는 TTS 생성 호출과 상태 반영 중심으로 확인
- 실제 오디오 재생 품질은 실기기 전용 항목에서 다시 확인

### A-6. 표현 목록 / 상세
- [ ] `expressions` 탭 목록 조회 가능
- [ ] 검색 동작 확인
- [ ] 상세 진입 가능
- [ ] 표현 메모 저장 가능
- [ ] `표현 연습` 진입 가능

### A-7. 표현 연습
- [ ] `expression/[id]/practice` 진입 가능
- [ ] 문제 유형 선택 가능
- [ ] `문제 생성(시작)` 동작 확인
- [ ] 텍스트 답변 채점 가능
- [ ] 저장한 학습 설정이 기본 답변 모드에 반영되는지 확인
- [ ] 질문 TTS 자동 재생 on/off 설정이 메시지와 흐름에 반영되는지 확인
- [ ] 자동 녹음 시작 on/off 설정이 메시지와 흐름에 반영되는지 확인
- [ ] `이전 표현 / 다음 표현` 이동 가능

### A-8. 오늘의 복습
- [ ] `reviews` 탭 목록 조회 가능
- [ ] 카드 선택 가능
- [ ] 문제 유형 유지 동작 확인
- [ ] 텍스트 답변 채점 가능
- [ ] 저장한 학습 설정이 기본 답변 모드에 반영되는지 확인
- [ ] 질문 TTS 자동 재생 on/off 설정이 메시지와 흐름에 반영되는지 확인
- [ ] 자동 녹음 시작 on/off 설정이 메시지와 흐름에 반영되는지 확인
- [ ] 채점 후 STT 인식 문장/피드백 표시 구조 확인
- [ ] 정답 TTS 버튼 문구와 상태 표시 확인
- [ ] `다음 문제` 이동 정상 동작
- [ ] 마지막 카드 완료 화면 노출 확인

### A-9. 웹에서 가능한 실패 시나리오
- [ ] API 주소를 일부러 틀리게 넣었을 때 에러 메시지가 표시되는지 확인

- [ ] 비로그인 상태에서 일부 API가 401 처리 후 세션 정리되는지 확인
- [ ] 문장 수정 후 재진입해도 변경값 유지되는지 확인
- [ ] 생성한 표현이 목록/상세/복습에 일관되게 보이는지 확인


## B. 실기기에서만 꼭 다시 볼 것

### B-1. 연결 / 실행
- [ ] 앱 최초 실행 시 크래시 없는지
- [ ] 탭 이동이 정상인지
- [ ] 한글 표시/줄바꿈이 어색하지 않은지
- [ ] 로딩/에러 메시지가 비어 있거나 끊기지 않는지

### B-2. 마이크 권한 / 실제 녹음
- [ ] 마이크 권한 요청 팝업 노출
- [ ] 권한 허용 후 `녹음 시작` 가능
- [ ] 녹음 중 타이머 증가 확인
- [ ] `녹음 종료` 시 로컬 녹음 파일 정보 표시
- [ ] 수동 업로드 모드에서 `녹음 업로드 + 처리 시작` 정상 동작
- [ ] 자동 업로드 모드에서 녹음 종료 직후 업로드 시작
- [ ] 업로드 진행률 표시 확인
- [ ] 업로드 후 `recording/[id]`로 자동 이동 여부가 설정값대로 동작

메모:
- 짧은 녹음과 1분 이상 녹음 각각 1회씩 테스트 권장

### B-3. 실제 오디오 재생
- [ ] 표현 TTS 재생 가능
- [ ] 정답 TTS 재생 가능
- [ ] 채점된 음성 다시 듣기 가능
- [ ] 무음 모드 / 볼륨 상태에서도 재생이 예상대로 동작하는지 확인

### B-4. 음성 답변(STT)
- [ ] `reviews` 음성 답변 녹음 가능
- [ ] `expression practice` 음성 답변 녹음 가능
- [ ] 음성 업로드 -> STT -> 채점 흐름 확인
- [ ] 질문 TTS 후 자동 녹음 시작 타이밍이 자연스러운지 확인
- [ ] 권한 거부 후 다시 시도할 때 복구 가능한지 확인

### B-5. 네트워크 / 업로드 안정성
- [ ] 업로드 중 Wi-Fi를 잠깐 끊었을 때 실패 메시지가 표시되는지 확인
- [ ] 모바일 네트워크/와이파이 전환 시 비정상 상태가 남지 않는지 확인
- [ ] 긴 녹음 업로드 시 앱이 멈추지 않는지 확인


## 회귀 체크 포인트
- [ ] `settings` 저장 기능 추가 후 로그인 흐름이 깨지지 않았는지
- [ ] `record` 자동 업로드 옵션 추가 후 수동 업로드가 여전히 동작하는지
- [ ] `settings` 이동 후 복귀해도 `record` / `reviews` 상태가 비정상 초기화되지 않는지
- [ ] API Base URL 저장 기능 추가 후 기존 개발 기본값 분기가 유지되는지
- [ ] 학습 설정 추가 후 `reviews` 와 `expression practice`의 기본 UX가 서로 어긋나지 않는지
- [ ] `recording/[id]` 필터/표현 이동 추가 후 편집 저장/삭제 흐름이 깨지지 않는지

## 메모
- 오늘 개발 중에는 `모바일 웹/개발 프리뷰` 항목을 우선 돌리고, 네이티브 의존 기능은 실기기 단계로 넘긴다.
- 첫 실기기 QA에서는 기능 완성도보다 연결 안정성 확인이 우선이다.
- 특히 모바일에서는 `권한`, `네트워크`, `업로드`, `오디오 재생`이 웹보다 더 자주 깨지므로 이 구간을 집중적으로 본다.
